# MeeDoo Creator Manager — 产品需求文档（PRD）

版本：0.2 | 日期：2026-10-07 | 状态：可评审初稿，尚未开发
产品负责人：Jay；下文角色、优先级、性能目标和阶段划分为设计建议，待项目评审确认。

## 1. 产品目标与问题

构建一个围绕 Creator 合作全流程的内部管理系统。Agent 读取完整邮件会话、提取信息、准备回复；团队主要审核草稿，仅在政策缺失、商业条件变化或特殊情况时参与决策。

当前问题：
- Creator 信息、邮件、产品选择、条款、发货和交付记录分散，难以知道今天该处理谁。
- 手工复制条款容易使用过期政策，混淆不同 Creator 的例外。
- 缺少关联具体条款版本的接受记录，以及内容使用权和佣金跟踪。
- CSV 更新容易产生重复资料或覆盖人工维护状态。

首版闭环：导入 Creator → 邮件沟通与审核 → 选款测量 → 完整条款与 Clickwrap → 发货与合身确认 → 内容审核与发布 → 记录试用表现及待结算事项。

不将粉丝数量或 Agent 回复数量作为唯一成功指标。核心是减少每个有效合作的人工操作时间，同时避免错误承诺、重复发送和无依据的状态变化。

## 3. 用户、权限与语言

以下是建议权限模型。首版可由同一人兼任多个角色，但后端仍必须校验权限。

| 角色 | 可操作 | 限制 |
| --- | --- | --- |
| Admin / Jay | 配置集成、用户权限、审批政策和例外、审核发送、查看全部业务 | 不能代替 Creator 接受条款或改写接受历史 |
| Partnership Operator | 维护负责的 Creator、选款、草稿、任务和资料；发送权限可单独授予 | 不修改已接受条款，不批准超权限预算或全局政策 |
| Reviewer | 审核被授权范围内的邮件、内容和合同待发版本 | 草稿修改后必须形成新审批版本 |
| Fulfillment | 查看必要地址、产品和尺寸；更新发货、物流和换码 | 默认不查看无关邮件、佣金和政策配置 |
| Read-only | 查看授权业务报表与资料 | 无发送、导出敏感资料或修改权限 |
| Creator | 访问本人被邀请的表单、合同、上传页面与凭证 | 不访问内部 CRM、他人资料或内部 Agent 对话 |

参照现有后台，内部界面首版建议中文并预留英文切换，语言范围待确认，需求说明中文；Creator 页面与邮件默认英文。支持 Unicode 姓名和国际地址。
每个 Creator 一个主负责人，可有协作者；同一会话不能由不同成员重复发送。代理机构代表多个 Creator 时必须明确每个合作与代表权限，不能按邮箱强行合并。

项目文档不会恢复此前已取消的每两小时邮件检查任务。应用内同步机制在开发部署时单独配置。

视觉沿用已讨论的左侧导航、紫色主色、卡片和表格；截图已检查，视觉规范及估算 tokens 见 UI_SPEC；精确字体和 CSS 尚未提供。所有页面必须有加载、空态、错误、无权限和同步过期状态。
风险不能只靠颜色表达。移动端优先保证 Creator 表单、条款与上传；内部后台以桌面为主。

## 6. 核心用户旅程

### 6.1 常规沟通
新回复同步 → 获取完整 thread 和 Sent → 识别实际待处理问题 → 提取带来源的事实 → 应用已接受条款/当前政策 → 草稿进入审核 → 人工编辑或批准 → 发送前检查最新会话 → 确认发送结果 → 更新状态。
如果 Jay 已回复或 Creator 仅表示感谢，通常不生成新回复。

### 6.2 超出知识的请求
Creator 提出例外 → Agent 展示问题、现有政策、缺失决策及一个建议 → Jay 在 Ask Agent 讨论 → 保存本次决定 → 重建草稿。
“保存为政策”必须单独选择适用范围、有效期并批准。一次特殊待遇不会自动变成全局默认。

### 6.3 合作到发货
批准产品和测量 → 填齐合同变量 → 人工审核待发合同与邮件 → Creator 验证身份并主动接受 → 接受凭证入库 → 检查地址、库存、国家与全部发货门槛 → 发货 → 收货与合身确认。
条款接受不直接触发发货；有地址也不代表同意条款。

### 6.4 内容到试用评估
确认合身 → 计算制作期限 → 上传 → 审核或一次合理修改 → 批准 → 提供并测试链接、代码和 CTA → 发布并记录证据 → 开始试用期 → Day 15 初评 → 持续处理尾部归因与逐单退货验证 → 人工决定是否邀请升级。
完成内容工作不代表佣金已结清或许可计时结束。

## 7. 功能需求与验收

### CRM-01 Creator 列表与详情（P0）
字段：姓名、社媒账号、邮箱、狗资料、国家、来源、负责人、标签、合作阶段、等级、选款、尺码、最后联络时间、下一步动作、阻塞及截止日期。粉丝和互动数据必须显示来源与更新时间。
可按状态、国家、平台、负责人、来源、时间、回复情况及 Needs Action 筛选；支持排序和保存筛选。
一人可有多个社媒账号、狗和合作。合作记录独立保存条款与产品，不能覆盖历史。
验收：从一个 Creator 可查看两次不同合作及各自的合同/邮件；缺失数据以未知显示，不显示为零；主负责人变更留痕。

### CRM-02 CSV 导入与去重（P0）
流程：上传 → 编码/列预览 → 字段映射 → 校验与匹配预览 → 人工确认 → 导入报告。
稳定来源 ID 优先匹配，邮箱/社媒作为候选依据；重名不自动合并，代理邮箱共享需人工确认。
重复导入只更新被允许的来源字段，不覆盖人工状态、负责人和已接受条款。记录导入批次与字段来源。
错误行独立报告；可撤销尚未被后续业务修改的批次字段，已变化字段进入冲突处理。CSV 导出防止公式注入。
验收：同一文件导入两次不产生重复实体；错误行不导致静默丢失；所有合并预览可审查。
实际 15 列映射和清洗规则已写入 CSV_IMPORT_SPEC：553 行、491 个规范化账号候选、55 组重复；124 个非空邮箱字段中 67 个是直接有效格式邮箱候选，另 57 个需分类复核。

### PIPE-01 Pipeline 与任务（P0）
阶段与阻塞分开；拖拽阶段时显示并检查转换依据。PAID_ONLY 等结果与物流状态不混为一列。
每个开放合作需要下一步动作、动作负责人或等待对象；允许“等待 Creator”而非强制生成内部待办。
支持任务分派、截止日期、完成、延后及原因；同一来源事件不得生成重复任务。
验收：缺少接受证据时拖到 AGREED 被阻止；缺尺寸和地址能同时显示；人工修正要记录依据，不能制造虚假接受事件。

### MAIL-01 邮箱接入与同步（P0）
接入经授权的工作邮箱，识别 Jay 的发送别名；读取完整会话、Sent、收件/抄送人、附件元数据及 provider ID。
首次导入的时间范围由管理员选择；之后增量同步并显示最后成功同步时间、错误和待重试数。
未关联邮件进入待匹配队列；一条 thread 涉及多个合作时要求明确关联。
撤销授权后停止同步与发送，保留的历史数据按访问和保留政策处理。
验收：在 Gmail 外部发送的回复能进入当前会话并使旧草稿失效；同步缺页或失败不得标记会话完整。

### AGENT-01 自动分析与草稿（P0）
按 AGENT_SYSTEM 执行。展示最新来信摘要、当前事实、建议动作、草稿、引用的消息/政策、未知和冲突。
输入包括完整相关 thread、合作记录、接受条款、已批准政策、产品事实和人工修正；不得混入其他 Creator 私密数据。
Agent 可自动保存候选事实，关键字段如地址、选款、费率和合同接受必须通过来源与流程校验；冲突不得覆盖人工值。
可重试分析、重新生成、忽略建议；保留 Agent run 版本与错误。
验收：发送过条款但只在 Inbox 看见旧来信，不再起草重复条款；无知识支持的付款周期进入决策队列。

### AGENT-02 Ask Agent 与政策沉淀（P0）
在合作/草稿旁展开上下文对话，支持解释建议、补充事实、修改语气、决定本次例外。
保存决定时显示“仅本合作”或“提议通用政策”；后者必须经政策批准流程后生效。
验收：Jay 同意本次额外产品，不影响其他 Creator；新政策发布后相关未发送草稿标为需复查。

### MAIL-02 审核与发送（P0）
动作：Approve & Send、Edit、Ask Agent、Dismiss、Assign。
批准绑定正文、主题、To/CC/BCC、附件、发送身份、会话版本与引用政策。人工修改后必须批准新版本。
发送前刷新；出现新消息、附件缺失、未替换占位符、条款冲突或授权失效则阻止并说明原因。
发送状态：待审核、已批准、发送中、已发送、失败、结果待核实。超时后先查 Sent，不直接重发。
验收：双击仅发送一次；两名审核者并发操作不会产生重复邮件；结果不明时 UI 不显示已发送或允许盲目重试。
P1 批量审批必须逐封可见并排除过期、决策待定草稿。首版无自动发送。

### PROD-01 产品、尺寸和信息表单（P0）
维护批准 Lookbook/产品、颜色、SKU、尺寸指南版本及库存确认时间。
Creator 填姓名、合作邮箱、所选产品、女性测量、狗名/品种/体重/颈胸背尺寸与单位、地址及承运所需电话；只收业务所需字段。
支持草稿保存和缺项提示；已发货后改地址创建异常请求，不覆盖原 shipment。
朋友及狗赠品需额外批准；可辨认参与者的出现许可单独记录。
验收：单位明确，旧指南仍可追溯；库存未知不能承诺可发；当前尺寸命名未核实前不自动把 XSS 改为 XXS。

### AGR-01 合同与 Clickwrap（P0，必做）
按 CLICKWRAP_SPEC 实现独立合同页面和后台证据面板。草稿、已发出、已接受、过期、撤销、被替代分开显示。
支持完整条款/附件快照、版本、明确同意语言、身份验证、服务器接受时间、唯一凭证和下载。
新合同版本不能改变既有签约内容；已接受合同修改需要新实例及再次接受。
邮件“I agree”只在确认身份和确切条款后记录为独立的 EMAIL_ACCEPTANCE。
验收：打开页面或扫描链接不接受；过期/撤销/替换的邀请不能接受；重复点击返回同一凭证；后台用户不能代签。
Level 3 签名方式未确定，不宣称首版 Clickwrap 满足其全部签署要求。

### SHIP-01 发货、换码与反馈（P0）
发货队列显示协议、选款/尺寸、地址、库存和国家审批的全部门槛。记录包装、承运商、运单、发货与送达时间。
支持一个合作多个包裹、补发、换码；每个 shipment 保留当时地址和商品快照。
确认收到且合身后才开始制作计时。换码未解决时阻止内容到期误报。
收集女性与狗服饰的合身活动、初次质量印象和最重要改进建议。
验收：生成运单不等于发货；送达不等于合身；部分包裹到达不能自动判定全部履约完成。

### CONTENT-01 上传、审核和发布（P0）
Creator 安全上传原图、最终视频与约定 clean clips；显示进度、失败重试、数量与缺失项。支持经验证可访问的外链补充。
服务器限制文件类型/大小并检测风险文件；具体上限按存储方案配置，不静默压缩原始交付。
审核记录通过/修改原因、审核人、时间与版本；一次合理修改限额按合作条款检查。
发布批准后才能生成待审核的 tracking package。记录平台、账号、live URL、发布时间、披露/CTA 证据和下架原因。
验收：收到一个文件不代表交付完成；第二次修改需人工例外；诚实负面反馈不能被自动改写为好评。

### RIGHTS-01 内容使用许可（P0）
按被接受合同保存每项素材的使用范围、交付时间、organic 到期、paid 激活截止、通知记录、首次付费展示及 paid 到期。
首版人工录入广告使用事实，显示来源；缺少首次展示数据时显示未知，不猜测剩余许可。
导出素材时提示可用范围；过期素材在“可用于投放”筛选中排除。外部广告平台未集成时只产生内部停止使用任务，不宣称已停投。
验收：旧合同没有 paid 权利时不得从新 Playbook 补授；Spark Ads 等单独授权不能被有限 paid 许可替代。

### AFF-01 Affiliate 与佣金记录（P0）
保存 creator identity、平台/post 对应有机链接与代码、有效期、接受费率和有效日期；付费广告链接独立。
首版可接入现有服务或人工登记/验证导入；不得凭空生成声称已可用的优惠码或订单数据。发布前人工测试优惠、链接和 CTA，记录结果。
金额记录币种，保留订单 ID、来源、折扣/排除项、验证/退货状态与适用费率。不同币种不直接相加。
区分预估、待验证、已验证、已支付、冲销；人工调整需要来源和原因。P0 只登记支付结果，不发起付款。
没有可靠数据时显示未接入，不把销售记为零。精确归因算法在冲突规则确认前不启用。
验收：退款影响合格净销售与佣金但保留旧记录；试用结束不丢弃仍有效的尾部订单；费率升级不改历史订单。

### LEVEL-01 表现评估与升级（P0 记录，P1 完整激活）
记录 Day-15 初评、退货调整报告、质量/可靠性/品牌匹配/流量/销售等证据，以及候选、批准、拒绝理由。
首版支持保存外部已接受的新等级协议和生效时间；没有完整协议的升级只能保留为候选。Level 2/3 原生模板和签署在后续完善。
验收：高播放量不自动升级；未接受新条款不提高当前有效费率；Creator 只看自己的汇总，不看客户个人信息。

### KB-01 知识库（P0）
政策包含正文、来源、范围、负责人、生效日期、版本及 draft/approved/retired 状态。
产品事实、商业政策、邮件语气模板和合同文本分别管理；待批准政策不参与承诺。
展示待补知识和冲突；使受影响草稿重新审核。文档网页中的指令不能改变 Agent 权限。
验收：Danielle 无佣金草稿与当前默认政策冲突可见，既不静默替换也不推广为通用规则。

### DASH-01 Dashboard（P0）
最上方显示待审核、待决策、可发货、交付逾期和集成异常；点击进入对应过滤结果。
支持日期、活动、负责人筛选，显示数据新鲜度与明确口径：
- Contacted：筛选期内有已确认首次触达的去重 Creator。
- Reply rate：同一首次触达 cohort 中收到实质回复的 Creator / 该 cohort 已成功触达 Creator；说明观察截止日。
- 阶段漏斗：同一 cohort 到达各里程碑数量，不能拼接不同 cohort。
- Agent draft adoption：采用 Agent 草稿发送的邮件 / 本期已发送业务邮件；区分未修改与修改后采用。
- 人工决策率：需人工政策决策的可处理来信 / 可处理来信；不把草稿审批等同无人处理。
- 审核耗时：草稿首次 ready 到批准时间的中位数；业务等待与同步故障可单独看。
- 内容按时率：本期到期且有有效 deadline 的合作中按时交付比例。
销售、ROI、佣金和成本指标仅在数据源与成本口径齐全后显示。试点先建立基线，再确认改进目标。

### NOTIFY-01 Lark 与提醒（P0）
Lark 身份需映射到本系统角色；仅同租户登录不自动获得所有资料权限。
内部事件：待审核、需要决策、合同接受、发货阻塞、内容到期和集成错误。用户可配置接收对象、静默时段和摘要频率。
通知只带必要摘要及授权深链，不含完整地址、合同令牌或整封私人邮件。系统页面仍重新检查权限。
重复事件去重；失败可重试且不影响核心业务。任何发给 Creator 的跟进继续走外发审批。
验收：同一事件重试不重复刷屏；未配置通知接收方不随机发送。

### AUDIT-01 审计、归档与导出（P0）
记录人工/Agent/系统 actor、时间、对象、变更前后、原因和来源；可按合作查看时间线。
支持权限控制的业务导出和合同证据导出，敏感导出需留痕。Creator 归档不删除历史履约与结算。
正常 UI 不提供抹除接受证据的操作；数据删除与保留请求按管理员流程和确定后的保留规则处理。
验收：能解释一个状态、字段、草稿和费率为何变化；应用日志不包含 OAuth token 或合同访问 token。

## 9. 时间与状态规则

存储 UTC 时间，UI 按用户时区显示；Creator 发布 deadline 必须包含当地时区。日历天、月份和精确截止规则由政策配置，不直接用固定小时数替代所有日历计算。

| 时钟 | 起点 | 结束 / 规则 |
| --- | --- | --- |
| 内容制作 | 收货且正确合身确认 | 五个日历天；换码异常需明确重排 |
| Level 1 试用 | 批准内容发布 | 15 天 |
| Level 1 新点击/代码开放 | 发布 | 15 天，到期停止新活动 |
| Level 1 顾客归因 | 活跃期内首次有效点击 | 15 天，后续点击不重置 |
| 订单验证 | 每笔订单及适用退货规则 | 各自 rolling hold |
| Organic license | 内容交付 | 12 个月 |
| Paid activation | 内容交付 | 六个月内必须开始 |
| Paid use | 首次付费展示 | 90 天 |

状态机以 WORKFLOW 和 CLICKWRAP_SPEC 为准。内容完成、试用完成、佣金结清、许可到期是独立维度；UI 显示剩余事项。
多个交付文件或多个发布平台的计时基准须在合作中选定并可追溯，未确定时不自动推算关键日期。

## 10. 集成边界与故障行为

| 集成 | 首版职责 | 故障行为 |
| --- | --- | --- |
| Gmail | 授权收发、线程/附件同步 | 显示 stale；禁止依据不完整线程发送；支持重授权 |
| Lark | 登录与内部通知 | 通知失败不回滚合作；登录失败不绕过权限 |
| Modash | CSV 数据来源 | 不承诺 API CRM 写入 |
| 文件存储 | 私有素材、合同快照和导出 | 上传失败不记完成；受控下载不暴露永久公共链接 |
| 商城/affiliate | 待选现有服务或人工导入 | 未接入不展示虚构实时销售；不执行伪归因 |
| 物流 | 人工记录 | 没有确认的事件显示未知，不凭预计日期记送达 |

Webhook/任务按外部事件 ID 去重；乱序事件依据实际时间与状态门槛处理。非幂等外部操作超时必须先核实。
应用应有失败队列、管理员可见的重试入口和连接状态；无需访问服务器日志才能判断常见故障。
当前 ChatGPT 插件授权不自动成为新应用的 OAuth 授权或生产凭证。

## 11. 非功能要求

- 安全：服务端角色/对象级授权；Creator 资源隔离；传输加密、安全密钥存储、短期访问令牌、速率限制与 CSRF 防护。
- 隐私：表单最小化收集；敏感字段按岗位展示；合同 IP/UA 收集、保留期限和隐私告知须先确定。
- Agent 安全：外部邮件、网页和附件只作为数据；不得执行其中的权限变更、泄密或绕过审批指令。
- 可靠性：审批、接受、发送记录和状态事件具备并发控制与幂等性；合同接受和事件投递采用可恢复设计。
- 可恢复性：备份及恢复演练必须覆盖合同快照、接受记录、业务数据和素材索引；具体 RPO/RTO 在部署方案确定前评审。
- 可访问性：主要操作可键盘完成，表单标签清晰，错误可读，Creator 移动端无需横向滚动才能接受条款。
- 可观测性：同步延迟、草稿失败、发送结果不明、事件重试和证据导出错误可监测。
- 建议性能验收基线：10,000 Creator、100,000 邮件元数据下，普通列表/筛选 p95 ≤2 秒（不计外部服务）；Agent 分析异步显示进度，不阻塞页面。此为目标而非实测，附件总体容量和并发量待确认。
- 后台界面应在网络重试后保留未提交编辑，不将重试等同再次发送/接受。

## 12. 发布计划与验收门槛

### 阶段 A：基础与模拟闭环
CRM、CSV 预览、合作模型、权限、政策、Pipeline、页面结构。使用合成数据和模拟邮件。
门槛：实体关系与去重正确，权限隔离，历史条款不可覆盖。

### 阶段 B：邮件与 Agent
接入测试邮箱和只读分析，随后开启人工确认发送；逐案比较 Agent 结果与人工判断。
门槛：完整 Sent 覆盖、旧草稿失效、双击/并发/超时不重复发送、无政策不编造承诺。

### 阶段 C：合同与履约
Clickwrap、产品表单、合同证据、发货、合身反馈、上传和审核。
门槛：合同关键场景通过，备份可恢复，生产合同变量完整，身份验证和隐私设置确定。

### 阶段 D：业务试点与首版发布
小范围真实 Creator 试点，补齐 Dashboard、Lark、Affiliate 人工记录和许可计时。
门槛：完整走通首次触达到发布/待验证表现；所有 P0 功能有结果与异常态；无未解决的越权访问、重复发送、错误接受和证据丢失问题。
后续 P1 按试点反馈排序，不以已写文档代表已上线。

## 17. 从 Sent 建立联系方式与接手沟通（2026-10-07，Jay 修正）
不建设 Modash 邮箱补全、回传或 CONTACT_ENRICHMENT 导入流程。Jay 在实际工作邮箱直接发送首次邮件；平台同步该邮箱 Sent 与完整 thread，从真实发送记录获得收件地址并接手后续沟通。Modash 内如何找到邮箱不属于本平台首版职责。

### SENT-01 已发送邮件发现（P0）
- 同步经授权工作邮箱的 Sent，包括 Jay 在 Gmail 或其他客户端手动发出的邮件和已配置发送别名。初始历史范围由管理员选择，之后增量同步。
- 以 provider message/thread ID 去重，保存实际发送时间、发送身份、To/CC/BCC 可见元数据和正文。只使用 provider 实际返回的字段；不推测不可见收件人。
- 仅对可判定为 Creator 业务的会话提出关联；普通工作邮件不自动进入 Creator CRM。分类不确定时进入“待识别/待关联”，不自动起草或发信。
- 优先用已有 thread 关联、已确认联系人映射、正文或签名中的明确社媒账号匹配 Creator。仅凭姓名相似或主题不能自动确认。
- 无对应 Creator 时可创建待审核候选，或让 Jay 从现有名单选择；候选不直接成为已确认 Creator。
- 保存邮箱来源为 sent_message，并链接到真实消息。已发送不等于地址已验证、一定可送达或合同已接受。
- 多收件人、代理代表多个 Creator、共享邮箱等情况需确认角色与合作；不能把所有收件人都当作 Creator 或因相同邮箱合并。
- 确认关联后按真实发送内容记录 CONTACTED 或其他有证据的阶段；无法确认时保留候选事件，不污染正式 Pipeline。
- 已发送后通常进入 Waiting for Creator；新回复触发 Agent 分析与草稿审核。不自动再发首次 outreach。
- 发送退信保留历史触达记录，单独标记投递失败和联系阻塞；不能仅凭 Sent 存在就算成功送达。
- 如已同步到 Creator 后续回复，按完整时间线识别当前动作，不能仍显示等待回复。
